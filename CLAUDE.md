# CLAUDE.md

The frontend for the Buraq Growth Suite: a Next.js 16 + Tailwind 4 app (light agfintax.com theme) with four modules. It replaced the former Streamlit app and has no backend code of its own.

- **Modules:** `src/app/ad-generator` (Ad generator), `src/app/lead-source` (Lead source) and `src/app/zoho-integration` ("Export leads to Zoho": leads from RDS by date range → Zoho CRM + a Campaigns list, via the `zohoexport` backend) and `src/app/bitrix-export` ("Bitrix24 Export": Bitrix24 leads by date range with a category filter, via the `bitrixexport` backend). Every lead source lands its output in the **Lead Hub** (AWS RDS, served by the `leadhubexport` backend; page `src/app/lead-hub`: load leads by date with `GET /leads?from&to`, filter by source, sync selected or all to Zoho CRM Contacts through the Zoho module's `/zoho/crm/contacts`): Lead Finder sends reviewed leads through its own backend's `/export-to-lead-hub` ("Export to Lead Hub"), Bitrix24 Export through its backend's `/exportToLeadHub`. Both send only leads a person has ticked and confirmed (human approval); each backend posts them to the real Lead Hub API (`leadhubexport`, configured in that backend as `LEAD_HUB_API_URL`). Each talks to its own backend; never point one module at another's backend (the Lead Hub page's use of the Zoho export endpoint is the one deliberate exception).
- **Proxies:** the browser only calls `/api/ad/*`, `/api/lead/*`, `/api/zoho/*`, `/api/bitrix/*` and `/api/hub/*`; `src/app/api/{ad,lead,zoho,bitrix,hub}/[...path]` forward allow-listed endpoints to the matching backend (`src/lib/server/`). New backend endpoints must be added to the allow-list.
- **Backend URLs:** Ad generator uses `AD_GENERATOR_BACKEND_URL` → `BACKEND_BASE_URL`. Lead source uses `LEAD_SOURCE_BACKEND_URL` → legacy `BACKEND_URL` → `backend.default_url` in `src/config/lead-source.json`, and must NOT fall back to `BACKEND_BASE_URL` (that is the Ad generator's backend). Zoho integration uses `ZOHO_INTEGRATION_BACKEND_URL` only; Bitrix export uses `BITRIX_EXPORT_BACKEND_URL` only, plus `BITRIX_EXPORT_API_KEY` (sent server-side as `X-API-Key`). The Lead Hub uses `LEAD_HUB_BACKEND_URL` only (unset = not connected yet). API contracts are in the README.
- **Lead source UI config** is data, not code: `src/config/lead-source.json` (optionally overridden from S3 / a file via `STREAMLIT_CONFIG_S3_URI` / `STREAMLIT_CONFIG_FILE`; names kept for deployment compatibility). Add industries, states, roles, provider labels there. City suggestions per state are `geography.state_areas` (cities only, no counties). Every provider in `provider_labels` is used on every run (not shown in the UI). Runs are never saved automatically (`persist_to_database: false`): a person reviews the leads and sends them with "Export to Lead Hub" (`/export-to-lead-hub` on the Lead source backend, which posts them to the Lead Hub's `/webScrapingLeads`). The page uses only the backend's V2 pipeline, as a background job (`/v2/sourcing-jobs`, polled for live progress, leads so far and token/search cost).
- **No shared code with either backend.** Never import from a backend project. Values mirrored from a backend (e.g. ad countries) are kept in sync by hand. No backend changes are needed for frontend work.
- **Theme:** brand palette lives in `src/app/globals.css` (`@theme`).
- **Env:** `.env.example` → `.env` / `.env.local`. Frontend-only keys; the only secret is `BITRIX_EXPORT_API_KEY`, which never reaches the browser.
- **Deployment:** Docker (standalone build, port 3000) on ECS Fargate + ALB. See README.
- Checks: `npm run lint` and `npm run build` (there are no tests).
